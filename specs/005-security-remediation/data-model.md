# Data Model: Security Remediation

**Feature**: 005-security-remediation | **Date**: 2026-10-28

This feature adds **no database tables or columns**. The entities below are runtime state: a signed token, Redis counters, and configuration.

---

## Admin Session

A signed JWT carried in the `admin_session` cookie. Never returned in a response body.

| Claim / attribute | Value | Notes |
|---|---|---|
| `username` | Admin username | Must match `ADMIN_USERNAME` at login. |
| `role` | `admin` | Existing claim, kept. |
| `jti` | Random UUID (`crypto.randomUUID()`) | New. Basis for the CSRF token. |
| `iat` / `exp` | Issue time; issue time + 24 h | Lifetime unchanged (spec assumption). |
| Signing key | `JWT_SECRET` (≥ 32 chars, validated at startup) | Fallback removed. |

**Cookie attributes**:

| Attribute | Value | Reason |
|---|---|---|
| Name | `admin_session` | |
| `HttpOnly` | true | Page scripts cannot read it (FR-012). |
| `Secure` | true | Sent only over HTTPS (FR-013). |
| `SameSite` | `None` (option A) | Cross-site requests from the frontend domain (FR-013). Revisit if option B is chosen; see research.md §1. |
| `Path` | `/` | |
| `Max-Age` | 86400 | Matches JWT lifetime. |

**State transitions**:

```
(no cookie) --login ok--> Active --logout--> (cookie cleared)
Active --exp passes--> Expired (treated as no cookie)
Active --secret rotated--> Invalid (signature fails)
```

**Validation rules**: Missing cookie → 401. Signature or expiry fails → 401 and cookie cleared. Non-GET request without a valid `X-CSRF-Token` → 403.

## CSRF Token

**Not stored.** Derived per request:

```
csrfToken = HMAC-SHA256(key = JWT_SECRET, message = "csrf:" + jti)   (hex)
```

| Property | Rule |
|---|---|
| Returned by | `POST /api/admin/login` and `GET /api/admin/validate` |
| Held by | Frontend `App.tsx` state (memory only) |
| Sent as | `X-CSRF-Token` header on POST, PUT, DELETE |
| Checked by | Recomputed from the cookie's `jti`; compared with `timingSafeEqual` |
| Lifetime | Same as the session it is derived from |

## Login Failure Counter

Redis key per client address.

| Field | Value |
|---|---|
| Key | `admin:login:fail:<ip>` |
| Value | Integer failure count |
| TTL | 900 s, set when the key is first created (fixed 15-minute window from the first failure) |
| Limit | Blocked when value ≥ 5 |
| Increment | On each failed login (wrong username or wrong password) |
| Reset | `DEL` on successful login |
| Unavailable Redis | Skip the counter; global rate limit still applies; log `warn` |

**State**: `Clear (0–4 failures)` → `Blocked (≥ 5, until TTL expires)`. A block cannot be ended early by a correct password.

---

## Submission Counter

Redis key per client address and endpoint.

| Field | Value |
|---|---|
| Key | `submit:<endpoint>:<ip>` where endpoint is `suggested_books` or `contact_form` |
| Value | Integer accepted-submission count |
| TTL | 3600 s, set at creation (fixed hourly window) |
| Limit | Blocked when value ≥ 10 |
| Increment | After human verification passes and the request is otherwise valid |
| Unavailable Redis | Skip; log `warn`; human verification still required |

---

## Admin Password Hash

Configuration, not stored state.

| Field | Value |
|---|---|
| Variable | `ADMIN_PASSWORD_HASH` |
| Format | bcrypt, 60 characters, prefix `$2a$`, `$2b$`, or `$2y$`, cost 12 |
| Generated by | `npm run hash-password` (reads from stdin) |
| Validation | Checked at startup; invalid or missing → refuse to start |
| Replaces | `ADMIN_PASSWORD` (plain text), which is no longer read |

---

## Turnstile Verification

External, per request. Not stored.

| Field | Source |
|---|---|
| Token | Request header `X-Turnstile-Token` (from the widget) |
| Secret | `TURNSTILE_SECRET_KEY` |
| Client address | Request IP (`req.ip`, trusted proxy 1) |
| Outcome | `success: true` → continue; `false` → 403; no response within 5 s → 503 |

---

## Object Storage Configuration

| Setting | Source | Used by |
|---|---|---|
| Endpoint and scheme | `MINIO_URL` | Single shared MinIO client (`utils/config.ts`) |
| Bucket | `MINIO_BUCKET_NAME` (required) | Uploads and presigned URLs |
| Credentials | `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY` | Shared client |

**Invariant**: Uploads and presigned links use the same client and bucket name, so a link always points at the bucket that holds the image.

## Image Upload Content

Not persisted separately; the file is written to the bucket with a derived content type.

| Detected type | Extension used (when ISBN given) | Stored `Content-Type` |
|---|---|---|
| JPEG | `.jpg` / `.jpeg` as given | `image/jpeg` |
| PNG | as given | `image/png` |
| WebP | as given | `image/webp` |
| GIF | as given | `image/gif` |
| Other / unrecognized | — | rejected |
