# Implementation Plan: Railway CI/CD Pipeline & GitHub Integration

**Branch**: `002-railway-cicd-pipeline` | **Date**: 2026-07-01 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-railway-cicd-pipeline/spec.md`

## Summary

Configure Railway to auto-deploy the development environment from the `development` branch and the production environment from `main`, with full database, Redis, and object storage isolation between environments. Deliver repository documentation covering local setup, Railway configuration, a complete environment variable reference, and a branching workflow checklist so any developer can reproduce either environment from scratch and verify changes at each tier before promoting them.

## Technical Context

**Language/Version**: TypeScript — Node.js 18+ (backend), TypeScript + React 18 (frontend)

**Primary Dependencies**: Express (backend HTTP), Vite (frontend build), mysql2 (database), minio SDK (object storage), redis (caching), jsonwebtoken (auth)

**Storage**: MariaDB/MySQL (one isolated instance per environment), MinIO S3-compatible object storage (one bucket per environment — already provisioned), Redis (one instance per environment)

**Testing**: No automated test suite — manual verification against the quickstart checklist

**Target Platform**: Railway PaaS (Linux containers), GitHub (source control + branch protection)

**Project Type**: Full-stack web application with Railway-hosted CI/CD pipeline

**Performance Goals**: Auto-deployment completes within 10 minutes of a branch merge (SC-002, SC-003)

**Constraints**: No external CI/CD service — Railway's built-in GitHub integration handles builds and deployments. All verification is manual.

**Scale/Scope**: Two Railway environments (development + production), three tiers of deployment (local / dev / prod), one Railway project with multiple environments

## Implementation Notes

- **Railway GitHub integration**: Configured in the Railway dashboard (not in code). Each environment is linked to a branch; Railway auto-deploys on push. No GitHub Actions workflow is needed for deployment.
- **`.env.example` files**: Template files with all variable names, blank or example values, and inline comments. Checked into git; actual `.env` files remain gitignored.
- **`docs/env-vars.md`**: Derived from `data-model.md`. Written for a human audience — includes purpose, which environments require each variable, and a safe example format. This is the single source of truth; `data-model.md` is the technical specification.
- **`docs/railway-setup.md`**: Step-by-step Railway UI walkthrough. Covers: create environments, link GitHub integration, add services (backend, frontend, MariaDB, Redis), set environment variables per environment.
- **`docs/workflow.md`**: Defines the three-tier branching policy, merge rules (PR required, tests pass), environment promotion checklist (pass quickstart tier N before merging to tier N+1), and hotfix procedure for emergency `main` patches.
- **CodeQL update**: Add `development` to the `branches` list under `pull_request` in `.github/workflows/codeql.yml` so security scanning runs on all PRs to development as well as main.
